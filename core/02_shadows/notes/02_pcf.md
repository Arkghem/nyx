# 02 PCF：把「比较」变成「平均」，以及它没解决什么

> P0/P1 的实测记录。所有数字来自 `shadow_basic`，1080p，Mitsuba/ray-cast 真值，
> Release 构建，best-of-3，p95。场景只有 50 个三角形——这是理解数字的前提。

---

## 1. PCF 做了什么

硬 shadow map 的可见性是二值的：

```
V(x) = (receiver_z <= stored_z + bias) ? 1 : 0
```

PCF（Reeves, Salesin, Cook 1987）把一次比较换成 \(N\times N\) 次比较的平均：

```
V(x) = (1/N²) Σ_{tap} (receiver_z <= stored_z(tap) + bias)
```

关键点：**平均的是比较结果，不是深度**。对深度做线性插值会得到一个不存在的
中间深度，PCF 的定义避免了这一点。硬件 compare sampler 的 2×2 PCF 本质上也是
在每个 tap 上做比较，再把结果按双线性权重混合。

PCF 的收益是阴影边缘的锯齿/走样变软；代价是每个像素 N² 次深度采样，
以及**它不会产生真正的半影**：半影宽度由光源大小和遮挡物/接收面距离决定，
而 PCF 的核宽度是屏幕/阴影图空间的常数，和物理量无关。接触硬化要靠 PCSS。

---

## 2. 实现

- shadow map 是 D32F；方向光正交投影，2048²（可 `--shadow-size`）。
- `shaders/visibility.metal` 在 compute 里手动比较：`depth2d` + 普通 sampler
  读深度，循环 `taps × taps` 个 tap，输出 `lit / samples`。
- `taps=1` 是 SM；3/5 是 PCF。核是 box，还没有 rotated Poisson。
- 采样 uv 的 y 要翻转：shadow map 的 render pass 已经经 viewport 翻过一次，
  compute 里的纹理坐标是 top-left 原点，所以要再翻一次。
- `bias` 是比较空间的 NDC z 偏移，默认 1e-3；光栅器 depth/slope bias 默认 0。
- 硬件 compare sampler 的版本还没有接；当前数字都是手动比较。

## 3. 测量

### 3.1 固定 2048² shadow map

| pipeline | taps | mask IoU | MAME | acne | peter-pan | soft 像素 | p50 ms | p95 ms |
|---|---|---|---|---|---|---|---|---|
| `sm` | 1 | 0.999760 | 0.000238 | 0.0031% | 0.0208% | 0.000% | 0.308 | 0.320 |
| `pcf3` | 9 | 0.999758 | 0.000661 | 0.0027% | 0.0213% | 0.186% | 0.319 | 0.343 |
| `pcf5` | 25 | 0.999756 | 0.001113 | 0.0027% | 0.0215% | 0.355% | 0.397 | 0.430 |

参照是**硬** ray-cast mask（方向光，精确）。IoU 几乎不变，MAME 变差，
soft 像素比例随 tap 数增加——这不是「PCF 更准」，而是「PCF 把硬边换成了模糊带」。

### 3.3 怎么读这张表

- **IoU 和 MAME 给出相反的结论。** 256² 上 PCF3 的 IoU 从 0.9963 升到 0.9973，
  但 MAME 从 0.00366 涨到 0.00854。原因是二值 IoU 只看 0.5 阈值两侧，
  PCF 把边界摊成中间值，减少了「本来该亮却被判黑」的 hard acne；
  但相对于精确硬边界，它引入了模糊误差。**指标选择决定了结论。**
- **soft 像素比例**是 PCF 核宽度的直接体现：256² 时 4–6%，1024² 时 0.5–0.8%，
  2048² 时 0.2–0.4%。它比 edge 宽度稳定；`edge_transition_px` 是屏幕空间的
  连续 run 宽度，受掠射角/多条边影响，只作为粗略参考，不是物理半影。
- **shadow map 尺寸在这个负载下几乎免费**：SM 在 256/1024/2048 都是 ~0.30 ms
  （p50 0.296–0.308）。场景只有 50 个三角形，shadow pass 的几何/带宽成本可以忽略，
  帧时间被 G-buffer 和全屏 compute 主导。这是一个真实结论，但也说明
  **这个场景不能用来判断「阴影分辨率预算」**；那是 P4 长场景/P6 密集场景的任务。
- **PCF 的 tap 成本是唯一可测差异**：p50 从 0.308（SM）到 0.319（9 taps）到 0.397
  （25 taps）。SM/PCF3 的跑间 p95 离散度约 5%；PCF5@2048 有一次被环境打断的运行
  （run1 的 p95 是 6.19 ms，p50 仍是 0.396 ms），best-of-3 选中了 0.43 ms 的干净结果。
  这说明两件事：单帧/单次测量不可用；p95 对偶发干扰敏感，所以还要看 p50 和离散度。
  每帧 8 次批处理把跑间 p95 离散度从 24.8% 压到约 5.9%，但它不能消除外部干扰。
- **acne 的定义**是「参考可见而 test 判黑」；**peter-pan** 是「参考被挡而 test 判亮」。
  256² 的 SM acne 0.36% 主要来自 shadow map 量化/走样，PCF 把它降到 0.22–0.25%，
  代价是 peter-pan 和模糊。bias 的完整取舍留给 P3。

## 4. 工业与学术位置

- PCF 是实时阴影的默认选项：Reeves 1987 之后，硬件 compare sampler 让它几乎免费
  （2×2 PCF 一次采样）。3×3/5×5/旋转 Poisson 是在质量和带宽之间调。
- PCF 解决的是**阴影图分辨率不足导致的边缘走样**，不是半影。半影需要光源尺寸，
  这就是 PCSS 的 blocker search + 可变核；再往后是可滤波表示（VSM/ESM/MSM）
  和虚拟分辨率（virtual SM）。
- PCF 的另一个问题在时间维度：固定核 + 移动相机/光源会闪烁；rotated Poisson/
  抖动核需要 TAA/降噪配合。本实验暂时只测静态帧，P3/P4 再看 temporal RMS。
- 工业上常见的组合是 CSM + PCF（太阳光）+ 屏幕空间接触阴影（近场细节）。
  PCF 是这条链里最便宜的一环，但它的质量上限被「核宽与物理半影无关」锁死。

## 5. 下一步

1. P2：矩形面积光 + PCSS，先把「接触硬化/半影」这个物理量做对；参照用面积光 MC，
   而不是硬 mask。PCF 的质量判卷也会换成软参照。
2. P2：VSM/EVSM/MSM。它们把「可滤波」做在表示上，代价是漏光和精度；
   `shadow_bleed` 场景会用「参考 umbra 内 test 判亮」的比例量化漏光。
3. P3：bias 扫描。把 acne、peter-panning、自阴影放在同一张曲线上，
   证明它们是同一个取舍的三个面。
4. 更重的场景：50 个三角形只能测「每像素 filter 成本」；要测分辨率/带宽，
   需要 P4 的长地面和更多遮挡物。

---

## 6. 结论

- PCF 是「用平均换锯齿」：相对硬参照，它不提高能量/边界精度，只把走样变成模糊；
  指标选 IoU 还是 MAME 会得到相反的排名。
- 在 50 三角形/1080p 的负载下，shadow map 尺寸几乎免费，PCF 的 tap 数是唯一
  可测的成本差异；这些毫秒数是**算法级**的，不是游戏帧率。
- 真正判断 PCF/PCSS 的参照必须是面积光软阴影；硬 mask 只适合校准和硬阴影验收。
